# List Resources and Import Bootstrap: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Draft, decisions D1–D3 open · **Owner:** Jens Hausherr · **Last updated:** 2026-10-23
**Related:** [[terraform-provider-resource-model]], [[implementation-plan]], [bootstrapping](../bootstrapping.md)

**Goal:** Bring the existing configuration of the staging and production stores under Terraform by discovering it with `terraform query` and importing it, and add resource types for anything configured there that is in scope but not yet supported.

**Architecture:** Every managed resource gets a resource identity and a matching list resource (`terraform-plugin-framework/list`). A temporary discovery command, run as a CI job with the read-only apps, first counts what exists per type, so the set of new resources is chosen from data. `shopify-provisioning` then runs `terraform query -generate-config-out` per env and turns the output into import blocks and HCL.

**Tech Stack:** Go, terraform-plugin-framework v1.19.0 (`list`, `resource/identityschema`), terraform-plugin-testing v1.16.0 (`querycheck`, `Query: true` steps), genqlient, Terraform ≥ 1.14 for `terraform query`.

**Spec:** this document plus [[terraform-provider-resource-model]] (import keys §2, per-resource sections) and CLAUDE.md (scope, conventions, safety).

## Global Constraints

- Admin API version stays **2026-10**. No new Go dependencies; framework and testing versions stay as in `go.mod`.
- Scope stays as in CLAUDE.md. Anything listed there as out of scope (app config/extensions/Functions, themes, products/collections/pages/discounts/metaobject entries, store creation, plan, billing, payments, domains, staff) is **not** implemented, even if discovery finds it. Phase-3 candidates (shop policies, checkout and branding) need an explicit decision first.
- `terraform import` with a string ID keeps taking the natural key, never a GID.
- Discovery and `terraform query` in CI run only with the read-only `<env>-plan` apps. No write credentials, no mutations.
- Discovery output may contain handles, names and counts, never tokens or metafield/metaobject values.
- Query acceptance tests use `tfversion.SkipBelow(tfversion.Version1_14_0)`; CI's Terraform matrix is `1.13.*`, `1.14.*` (`.github/workflows/test.yml`).
- Each task: `make fmt lint test` passes and `make generate` leaves no diff.

## Decisions needed before Task 3

- **D1: identity attributes.** Identity must never change for an object, but menu handle, market handle and location name are updatable. Proposal: identity is `{ id = <GID> }` for every resource. Natural-key string import stays as it is (CLAUDE.md). Identity-based import blocks are machine-generated by `terraform query`, so nobody types GIDs. Alternative: natural-key identity for metafield/metaobject definitions (immutable keys) and GID only for menu, market, location and delivery profile.
- **D2: read scopes for discovery.** The read-only apps only have the six `read_*` scopes. Metafield definitions for other owner types (CUSTOMER, ORDER, COMPANY…) probably need more read scopes, and ARTICLE/BLOG/PAGE need content scopes that [bootstrapping](../bootstrapping.md) says not to grant. Proposal: discovery reports `ACCESS_DENIED` per owner type as "scope missing"; widen scopes only for owner types you decide to manage.
- **D3: new resource types** (after Task 2). Pick from the discovery report. Candidates already in scope or flagged as next step by the docs: custom delivery profiles, web presences (`shopify_market_web_presence`), shop locales, metafield definitions for more owner types. Phase 3 (needs a separate decision): shop policies, checkout and accounts configuration.

## Review Focus

1. **Generated config round-trip:** `terraform query -generate-config-out` followed by `plan` must show only imports, no updates. Unmanaged optional attributes must stay null in the listed resource, or the first apply would overwrite admin edits. Owned by each list task, step "round-trip test".
2. **Existing state without identity:** Read must set identity when state has none (state written by the current provider). Owned by each identity task, test `ExpectIdentity` after a plain refresh step.
3. **Pagination and limit:** stores with more objects than one page (default page size 50), and `limit` smaller than one page. Owned by Task 3 (`patterns.Paginate` unit test).
4. **Partial access:** one metafield owner type returns `ACCESS_DENIED`; listing must continue with a warning, not fail. Owned by Task 4.
5. **Pattern A objects in lists:** default menus and the general delivery profile appear in list results; importing them must not trigger Create (adopt) or Delete. Owned by Tasks 6 and 8.
